Architecture

La recherche dans Atelier Lumière est propulsée par l'API Search de Wingify Commerce. Toutes les requêtes transitent par un proxy Express côté serveur afin d'éviter les restrictions CORS du navigateur. Le frontend ne contacte jamais directement l'API Wingify Commerce.

Navigateur
→
Proxy Express
/api/search · /api/autocomplete
→
Wingify Commerce
search-api.abtasty.com
abtId (Identifiant Wingify)
→
Index : {abtId}_Catalog

Il existe deux surfaces de recherche distinctes :

  • Menu déroulant de la barre de navigation — s'affiche sous la barre de navigation au fil de la saisie. Présente les suggestions d'autocomplétion dans la colonne gauche et jusqu'à 3 produits correspondants dans la colonne droite.
  • Page de résultats complète — une page search dédiée avec filtres à facettes, contrôles de tri et pagination par chargement progressif.

Identifiants & Configuration

L'intégration de la recherche nécessite un seul identifiant : l'Identifiant Wingify Commerce (appelé abtId en interne). C'est le même identifiant que celui utilisé pour votre implémentation Web Experimentation Wingify AB Tasty.

Nommage de l'index : L'API Search de Wingify Commerce utilise un index nommé {abtId}_Catalog. Par exemple, si votre identifiant est b0ffe524c1c6b488, votre index de recherche est b0ffe524c1c6b488_Catalog. Le proxy l'ajoute automatiquement — vous n'avez jamais à le construire manuellement côté frontend.

Proxy Côté Serveur

Deux routes Express jouent le rôle de proxies transparents. Leur unique responsabilité est de :

  1. Récupérer le abtId du visiteur depuis le magasin d'identifiants.
  2. Transmettre la requête à l'API Wingify Commerce avec l'index ou le client_id approprié.
  3. Retransmettre la réponse au navigateur.
Pourquoi un proxy ? L'API Wingify Commerce n'envoie pas les en-têtes CORS permettant les requêtes directes depuis le navigateur. Tous les appels de recherche doivent transiter par votre propre serveur.

Endpoint de Recherche

GET /api/search

// src/server.js
app.get('/api/search', async (req, res) => {
  const { text } = req.query;
  if (!text) return res.status(400).json({ error: 'text required' });

  const email = visitorEmailMap.get(req.visitorId);
  const c     = email ? credStore.get(email) : null;
  const abtId = c?.abtId || null;
  if (!abtId) return res.json({ hits: [], totalHits: 0, noIdentifier: true });

  // Transmet toute la chaîne de requête (text, hitsPerPage, page, filters, sort…)
  const rawQs = req.originalUrl.split('?')[1] || '';
  const index = encodeURIComponent(`${abtId}_Catalog`);

  const upstream = await fetch(
    `https://search-api.abtasty.com/search?${rawQs}&index=${index}`
  );
  const body = await upstream.json();
  res.status(upstream.status).json(body);
});

La chaîne de requête complète du navigateur est transmise telle quelle (incluant filters, sort, page, semanticRatio) — le proxy ajoute uniquement le paramètre index dérivé du abtId du visiteur.

ParamètreTypeNotes
textrequisLa chaîne de recherche
hitsPerPageoptionnelRésultats par page. Par défaut 12 sur la page complète, 3 dans le menu déroulant
pageoptionnelIndex de page à base zéro pour la pagination
semanticRatiooptionnelFlottant 0–1. 0 = mots-clés uniquement, 1 = entièrement sémantique (IA). Fixé à 1 dans la version actuelle
sortoptionnelEx. : price:asc, price:desc, name:asc
filters[champ][]optionnelFiltre de liste en notation entre crochets. Répétable : filters[couleur][]=Rouge&filters[couleur][]=Bleu
filters[price][N][operator]optionnelOpérateur de plage : >= ou <= (encodé en pourcentage)
filters[price][N][value]optionnelValeur numérique associée à l'opérateur ci-dessus

Endpoint d'Autocomplétion

GET /api/autocomplete

// src/server.js
app.get('/api/autocomplete', async (req, res) => {
  const { text, hitsPerPage } = req.query;
  if (!text) return res.json({ suggestions: [] });

  const abtId = /* …récupéré depuis credStore… */;
  if (!abtId) return res.json({ suggestions: [] });

  const params = new URLSearchParams({ client_id: abtId, query: text });
  if (hitsPerPage) params.set('hits_per_page', hitsPerPage);

  const upstream = await fetch(
    `https://search-api.abtasty.com/autocomplete?${params}`
  );
  const body = await upstream.json();
  res.status(upstream.status).json(body);
});
Index de suggestions : L'autocomplétion nécessite un index _Suggestions distinct côté Wingify Commerce (différent de _Catalog). Si aucune suggestion n'apparaît, contactez le support Wingify Commerce pour provisionner l'index de suggestions pour votre client_id.
ParamètreNotes
textChaîne de requête (transmise en tant que query= en amont)
hitsPerPageNombre maximum de suggestions à retourner (transmis en tant que hits_per_page=). Par défaut 5 dans le menu déroulant

La structure de la réponse est { suggestions: [{ text: "…" }, …] }. Chaque suggestion possède une propriété text utilisée pour remplir la colonne gauche du menu déroulant.

Menu Déroulant de Recherche

Lorsque l'utilisateur tape dans la barre de recherche de la navigation, un menu déroulant à deux colonnes apparaît sous le champ de saisie. La colonne gauche affiche les suggestions d'autocomplétion ; la colonne droite affiche jusqu'à 3 produits du catalogue. Les deux colonnes se mettent à jour indépendamment dès réception des réponses — l'API qui répond en premier est rendue immédiatement sans attendre l'autre.

Délai d'attente et AbortController

Pour éviter de surcharger l'API à chaque frappe, les requêtes sont déclenchées après un délai de 200 ms. Un AbortController est utilisé pour annuler toute requête en cours de la frappe précédente avant d'en lancer une nouvelle — cela empêche les résultats obsolètes d'écraser les résultats plus récents.

// public/index.html — _doNavSearch()
function _doNavSearch(query) {
  // Annule la paire de requêtes précédente
  if (_navAbort) _navAbort.abort();
  _navAbort = new AbortController();
  const { signal } = _navAbort;

  // Les deux s'exécutent indépendamment — le premier à arriver met à jour sa colonne
  (async () => {
    const res = await fetch(`/api/autocomplete?text=${encodeURIComponent(query)}&hitsPerPage=5`, { signal });
    const data = res.ok ? await res.json() : {};
    _navDropSuggestions = data.suggestions || [];
    _showNavDropdown(_navDropSuggestions, _navDropHits, _navDropTotalHits, query);
  })();

  (async () => {
    const res = await fetch(`/api/search?text=${encodeURIComponent(query)}&hitsPerPage=3`, { signal });
    const data = res.ok ? await res.json() : {};
    _navDropHits = data.hits || [];
    _showNavDropdown(_navDropSuggestions, _navDropHits, _navDropTotalHits, query);
  })();
}

Comportement au clavier

  • Entrée — ferme le menu déroulant et navigue vers la page de résultats complète pour la requête en cours.
  • Échap — ferme le menu déroulant sans naviguer.
  • Clic sur une suggestion — remplit le champ avec le texte de cette suggestion et déclenche une recherche complète.
  • Clic sur un produit — ouvre le lien du produit dans un nouvel onglet.
  • Clic sur « Voir tous les résultats » — navigue vers la page de résultats complète.
  • Clic en dehors du menu — le ferme.

Page de Résultats Complète

Naviguer vers la page search (via Entrée, « Voir tous les résultats » ou _viewAllSearch()) affiche une mise en page complète de résultats alimentée par le même proxy /api/search avec hitsPerPage=12.

Variables d'état

VariableRôle
_searchQueryTexte de recherche en cours, partagé entre la navigation et les résultats complets
_currentPageIndex de page à base zéro pour la pagination par chargement progressif
_accHitsTableau de résultats accumulés sur toutes les pages chargées
_lastFacetsDonnées de facettes issues de la dernière réponse
_activeFiltersMap de champ → Set<valeur> pour les filtres de liste actifs
_priceMin / _priceMaxValeurs actives du filtre de plage de prix
_sortByClé de tri active, ex. price:asc
_totalPages / _totalHitsTotaux issus de la dernière réponse

Pipeline de rendu

Après réception d'une réponse par _doSearch(), quatre fonctions de rendu s'exécutent en séquence :

_renderControls()

Affiche le nombre de résultats, un lien « Effacer N filtres » (si des filtres sont actifs) et le menu de tri au-dessus de la grille de produits.

_renderFacets()

Lit _lastFacets depuis la réponse et construit le panneau de filtres latéral. Les facettes de liste deviennent des puces à bascule ; les facettes de plage (comme price) deviennent des champs min/max. Les facettes sont masquées si la réponse n'en retourne aucune.

_renderAccHits()

Affiche _accHits sous forme de grille de produits. Chaque résultat montre une image produit (img_link), un nom (title ou name) et un prix. Cliquer sur une carte ouvre le link du produit dans un nouvel onglet.

_renderLoadMore()

Affiche un bouton « Charger N de plus » lorsque _currentPage < _totalPages - 1. Cliquer dessus incrémente _currentPage et appelle _doSearch(undefined, true) — le drapeau append ajoute les nouveaux résultats à _accHits plutôt que de les remplacer.

Facettes & Filtres

L'API Search de Wingify Commerce retourne un objet facets en parallèle des résultats. Chaque clé est un champ filtrable. Le proxy transmet cet objet sans modification.

Facettes de liste

Lorsqu'une facette possède "type": "list", ses valeurs sont un tableau de paires [valeur, nombre]. Le frontend affiche chaque paire sous forme de puce cliquable. Sélectionner une puce l'ajoute à _activeFilters[champ] (un Set) et relance la recherche.

Les filtres de liste actifs sont sérialisés dans la chaîne de requête en notation entre crochets :

filters[couleur][]=Rouge&filters[couleur][]=Bleu&filters[genre][]=Homme

Facettes de plage

Lorsqu'une facette possède "type": "range", ses values contiennent min et max. Celles-ci s'affichent sous forme de deux champs numériques et d'un bouton Appliquer. Les filtres de plage utilisent une notation structurée entre crochets :

// Prix >= 50 ET prix <= 200
filters[price][0][operator]=%3E%3D&filters[price][0][value]=50
filters[price][1][operator]=%3C%3D&filters[price][1][value]=200
Facettes absentes ? Les facettes doivent être configurées sur votre index de catalogue Wingify Commerce. Si le champ facets est absent ou vide dans les réponses de recherche, contactez le support Wingify Commerce pour activer les facettes sur les champs concernés de votre index.

Pagination

L'implémentation utilise un modèle de chargement progressif (et non une navigation de pages traditionnelle). L'index de page est suivi dans _currentPage et incrémenté à chaque clic sur « Charger plus ».

// Mode ajout — appelé par le bouton "Charger plus"
_doSearch(undefined, true);

// À l'intérieur de _doSearch() :
_accHits = append
  ? [..._accHits, ...(data.hits || [])]  // ajout
  : (data.hits || []);                   // remplacement

Tout changement de requête, d'ordre de tri ou de filtres réinitialise _currentPage à 0 et _accHits à [], reprenant depuis la première page.

Référence des Paramètres de Requête

L'ensemble complet des paramètres envoyés par la page de résultats est construit par _buildSearchParams(page) :

function _buildSearchParams(page) {
  const p = [
    `text=${encodeURIComponent(_searchQuery)}`,
    `hitsPerPage=12`,
    `page=${page}`,
    `semanticRatio=1`,    // recherche entièrement sémantique / IA
  ];
  if (_sortBy) p.push(`sort=${_sortBy}`);

  // Filtres de liste
  Object.entries(_activeFilters).forEach(([field, vals]) => {
    [...vals].forEach(v => p.push(`filters[${field}][]=${encodeURIComponent(v)}`));
  });

  // Filtres de plage de prix
  let ri = 0;
  if (_priceMin !== '') {
    p.push(`filters[price][${ri}][operator]=%3E%3D`);
    p.push(`filters[price][${ri++}][value]=${_priceMin}`);
  }
  if (_priceMax !== '') {
    p.push(`filters[price][${ri}][operator]=%3C%3D`);
    p.push(`filters[price][${ri}][value]=${_priceMax}`);
  }

  return p.join('&');
}

Structure de la Réponse

L'API Search de Wingify Commerce retourne les champs de premier niveau suivants (transmis sans modification par le proxy) :

{
  "hits":       [{ "title": "…", "price": 99, "img_link": "…", "link": "…" }],
  "totalHits":  42,
  "totalPages": 4,
  "page":       0,
  "facets": {
    "couleur": { "type": "list",  "values": [["Rouge", 12], ["Bleu", 8]] },
    "price":   { "type": "range", "values": { "min": 19, "max": 349 } }
  }
}

// Sentinel ajouté par le proxy lorsqu'aucun abtId n'est configuré :
{ "hits": [], "totalHits": 0, "noIdentifier": true }

Structure de la réponse d'autocomplétion

{
  "suggestions": [
    { "text": "parka alpine" },
    { "text": "parka chamonix" }
  ]
}
