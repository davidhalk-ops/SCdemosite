Architecture

Search in True North is powered by the Wingify Commerce Search API. All requests flow through a server-side Express proxy to avoid browser CORS restrictions. The frontend never contacts the Wingify Commerce API directly.

Browser
→
Express Proxy
/api/search · /api/autocomplete
→
Wingify Commerce
search-api.abtasty.com
abtId (Wingify Identifier)
→
Index: {abtId}_Catalog

There are two distinct search surfaces:

  • Nav search dropdown — appears inline below the nav bar as the user types. Shows autocomplete suggestions in the left column and up to 3 product hits in the right column.
  • Full search results page — a dedicated search page with facet filters, sort controls, and infinite scroll / load-more pagination.

Credentials & Setup

The search integration requires a single credential: the Wingify Commerce Identifier (called abtId internally). This is the same identifier used for your Wingify AB Tasty Web Experimentation implementation.

Index naming: The Wingify Commerce Search API uses an index named {abtId}_Catalog. For example, if your identifier is b0ffe524c1c6b488, your search index is b0ffe524c1c6b488_Catalog. The proxy appends this automatically — you never build it manually in the frontend.

Server-Side Proxy

Two Express routes act as transparent proxies. Their only job is to:

  1. Look up the visitor's abtId from the credential store.
  2. Forward the request to the Wingify Commerce API with the correct index or client_id.
  3. Stream the response back to the browser.
Why proxy at all? The Wingify Commerce API does not send CORS headers that allow direct browser requests. All search calls must be routed through your own server.

Search Endpoint

GET /api/search

// src/server.js
app.get('/api/search', async (req, res) => {
  const { text } = req.query;
  if (!text) return res.status(400).json({ error: 'text required' });

  const email = visitorEmailMap.get(req.visitorId);
  const c     = email ? credStore.get(email) : null;
  const abtId = c?.abtId || null;
  if (!abtId) return res.json({ hits: [], totalHits: 0, noIdentifier: true });

  // Pass the entire query string through (text, hitsPerPage, page, filters, sort…)
  const rawQs = req.originalUrl.split('?')[1] || '';
  const index = encodeURIComponent(`${abtId}_Catalog`);

  const upstream = await fetch(
    `https://search-api.abtasty.com/search?${rawQs}&index=${index}`
  );
  const body = await upstream.json();
  res.status(upstream.status).json(body);
});

The full query string from the browser is forwarded verbatim (including filters, sort, page, semanticRatio) — the only thing the proxy adds is the index parameter derived from the visitor's abtId.

ParameterTypeNotes
textrequiredThe search query string
hitsPerPageoptionalResults per page. Defaults to 12 on the full results page, 3 in the nav dropdown
pageoptionalZero-based page index for pagination
semanticRatiooptionalFloat 0–1. 0 = keyword-only, 1 = fully semantic (AI-powered). Hard-coded to 1 in current build
sortoptionale.g. price:asc, price:desc, name:asc
filters[field][]optionalBracket-notation list filter. Repeatable: filters[colour][]=Red&filters[colour][]=Blue
filters[price][N][operator]optionalRange operator: >= or <= (percent-encoded)
filters[price][N][value]optionalNumeric value paired with the operator above

Autocomplete Endpoint

GET /api/autocomplete

// src/server.js
app.get('/api/autocomplete', async (req, res) => {
  const { text, hitsPerPage } = req.query;
  if (!text) return res.json({ suggestions: [] });

  const abtId = /* …lookup from credStore… */;
  if (!abtId) return res.json({ suggestions: [] });

  const params = new URLSearchParams({ client_id: abtId, query: text });
  if (hitsPerPage) params.set('hits_per_page', hitsPerPage);

  const upstream = await fetch(
    `https://search-api.abtasty.com/autocomplete?${params}`
  );
  const body = await upstream.json();
  res.status(upstream.status).json(body);
});
Suggestions index: Autocomplete requires a separate _Suggestions index on the Wingify Commerce side (distinct from _Catalog). If no suggestions appear, contact Wingify Commerce support to provision the suggestions index for your client_id.
ParameterNotes
textQuery string (mapped to query= upstream)
hitsPerPageMax suggestions to return (mapped to hits_per_page= upstream). Default 5 in nav dropdown

The response shape is { suggestions: [{ text: "…" }, …] }. Each suggestion has a text property used to populate the left column of the nav dropdown.

Nav Search Dropdown

As the user types in the nav search bar, a two-column dropdown appears below the input. The left column shows autocomplete suggestions; the right column shows up to 3 product hits from the catalog. Both columns update independently as responses arrive — whichever API responds first is rendered immediately without waiting for the other.

Debounce & AbortController

To avoid flooding the API with every keystroke, requests are fired after a 200ms debounce. An AbortController is used to cancel any in-flight request from the previous keystroke before the new one fires — this prevents stale results from overwriting newer ones.

// public/index.html — _doNavSearch()
function _doNavSearch(query) {
  // Cancel the previous pair of fetches
  if (_navAbort) _navAbort.abort();
  _navAbort = new AbortController();
  const { signal } = _navAbort;

  // Both run independently — first to arrive updates its column
  (async () => {
    const res = await fetch(`/api/autocomplete?text=${encodeURIComponent(query)}&hitsPerPage=5`, { signal });
    const data = res.ok ? await res.json() : {};
    _navDropSuggestions = data.suggestions || [];
    _showNavDropdown(_navDropSuggestions, _navDropHits, _navDropTotalHits, query);
  })();

  (async () => {
    const res = await fetch(`/api/search?text=${encodeURIComponent(query)}&hitsPerPage=3`, { signal });
    const data = res.ok ? await res.json() : {};
    _navDropHits = data.hits || [];
    _showNavDropdown(_navDropSuggestions, _navDropHits, _navDropTotalHits, query);
  })();
}

Keyboard behaviour

  • Enter — dismisses the dropdown and navigates to the full search results page for the current query.
  • Escape — closes the dropdown without navigating.
  • Clicking a suggestion — fills the input with that suggestion text and triggers a full search.
  • Clicking a product hit — opens the product link in a new tab.
  • Clicking "View all results" — navigates to the full search results page.
  • Clicking outside the dropdown — closes it.

Dropdown DOM structure

The dropdown lives in a fixed-position #nav-search-dropdown div that is re-positioned on every render via _positionDropdown(), which reads the nav input's bounding rect to align the dropdown's right edge with the input's right edge.

Full Search Results Page

Navigating to the search page (via Enter, "View all results", or _viewAllSearch()) renders a full results layout backed by the same /api/search proxy endpoint with hitsPerPage=12.

State variables

VariablePurpose
_searchQueryCurrent search text, shared by nav and full-results
_currentPageZero-based page index for load-more pagination
_accHitsAccumulated hit array across loaded pages
_lastFacetsFacet data from the most recent response
_activeFiltersMap of field → Set<value> for active list filters
_priceMin / _priceMaxActive price range filter values
_sortByActive sort key e.g. price:asc
_totalPages / _totalHitsTotals from the last response

Render pipeline

After _doSearch() receives a response, four render functions run in sequence:

_renderControls()

Renders the results count, a "Clear N filters" link (when filters are active), and the sort-by dropdown above the product grid.

_renderFacets()

Reads _lastFacets from the response and builds the sidebar filter panel. List facets become chip toggles; range facets (like price) become min/max inputs. Facets are hidden if the response returns none.

_renderAccHits()

Renders _accHits as a product grid. Each hit shows a product image (img_link), name (title or name), and price. Clicking a card opens the product's link in a new tab.

_renderLoadMore()

Shows a "Load N more" button when _currentPage < _totalPages - 1. Clicking it increments _currentPage and calls _doSearch(undefined, true) — the append flag causes new hits to be appended to _accHits rather than replacing them.

Facets & Filters

The Wingify Commerce Search API returns a facets object alongside hits. Each key is a filterable field. The proxy forwards this object unchanged.

List facets

When a facet has "type": "list", its values are an array of [value, count] pairs. The frontend renders each pair as a chip button. Selecting a chip adds it to _activeFilters[field] (a Set) and re-fires the search.

Active list filters are serialised into the query string using bracket notation:

filters[colour][]=Red&filters[colour][]=Blue&filters[gender][]=Men

Range facets

When a facet has "type": "range", its values contains min and max. These render as two numeric inputs plus an Apply button. Range filters use a structured bracket notation:

// Price >= 50 AND price <= 200
filters[price][0][operator]=%3E%3D&filters[price][0][value]=50
filters[price][1][operator]=%3C%3D&filters[price][1][value]=200
Facets not appearing? Facets must be configured on your Wingify Commerce catalog index. If the facets field is missing or empty in search responses, contact Wingify Commerce support to enable faceting for the relevant fields in your index.

Pagination

The implementation uses a load-more pattern (not traditional page navigation). The page index is tracked in _currentPage and incremented each time the user clicks "Load more".

// Append mode — called by "Load more" button
_doSearch(undefined, true);

// Inside _doSearch():
_accHits = append
  ? [..._accHits, ...(data.hits || [])]  // append
  : (data.hits || []);                   // replace

Any change to the search query, sort order, or filters resets _currentPage to 0 and _accHits to [], starting fresh from page one.

Query Parameters Reference

The full parameter set sent by the full results page is built by _buildSearchParams(page):

function _buildSearchParams(page) {
  const p = [
    `text=${encodeURIComponent(_searchQuery)}`,
    `hitsPerPage=12`,
    `page=${page}`,
    `semanticRatio=1`,    // fully semantic / AI search
  ];
  if (_sortBy) p.push(`sort=${_sortBy}`);

  // List filters
  Object.entries(_activeFilters).forEach(([field, vals]) => {
    [...vals].forEach(v => p.push(`filters[${field}][]=${encodeURIComponent(v)}`));
  });

  // Price range filters
  let ri = 0;
  if (_priceMin !== '') {
    p.push(`filters[price][${ri}][operator]=%3E%3D`);
    p.push(`filters[price][${ri++}][value]=${_priceMin}`);
  }
  if (_priceMax !== '') {
    p.push(`filters[price][${ri}][operator]=%3C%3D`);
    p.push(`filters[price][${ri}][value]=${_priceMax}`);
  }

  return p.join('&');
}

Response Shape

The Wingify Commerce Search API returns the following top-level fields (forwarded unchanged by the proxy):

{
  "hits":       [{ "title": "…", "price": 99, "img_link": "…", "link": "…" }],
  "totalHits":  42,
  "totalPages": 4,
  "page":       0,
  "facets": {
    "colour": { "type": "list",  "values": [["Red", 12], ["Blue", 8]] },
    "price":  { "type": "range", "values": { "min": 19, "max": 349 } }
  }
}

// Proxy-added sentinel when no abtId is configured:
{ "hits": [], "totalHits": 0, "noIdentifier": true }
